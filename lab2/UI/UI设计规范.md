# 实验二 UI 设计规范

版本：v0.1（三屏样例阶段）  
工具：Figma 网页版  
画布：1440 × 900（桌面端）  
导出：PNG 2x，按 `01_登录注册.png` 这类名称放入 `UI界面/`。

## 1. 设计目标

- 覆盖实验一的 8 个业务模块，每个模块至少一屏；
- 体现四类角色的**入口差异、数据可见性和操作限制**；
- 静态高保真即可，不写前端代码；
- 视觉服务于信息层级：余票、状态、截止时间、权限提示必须一眼可见。

## 2. 设计系统

### 2.2 字体

- 中文：Noto Sans CJK SC / Microsoft YaHei；
- 数字与价格：同字体，价格加粗；
- 层级：H1 30–32、H2 22–24、H3 16–18、正文 13–14、辅助 11–12。

### 2.3 间距与圆角

- 8px 网格；页面左右边距 32px；
- 卡片圆角 14–16px，输入框/按钮 10–12px，标签 8–12px；
- 卡片间距 16px。

### 2.4 组件

按钮（主/次/幽灵/危险）、输入框、下拉、标签 Chips、状态徽章、活动卡片、票种行、表格、步骤条、提示条、空/加载/错误状态。

## 3. 九个界面与模块对应

| 编号 | 界面 | 角色 | 覆盖模块 | 关键状态 |
|---|---|---|---|---|
| UI-01 | 登录/注册 | 全部 | 账号 | 登录只需手机号+密码（一个手机号只对应一个身份）；注册卡选择身份；管理员/检票员入口；无找回密码；平台预创建提示只保留一处 |
| UI-02 | 活动浏览与详情 | 参与者 | 活动/场次、票种/容量、查询 | 售票中、即将售罄、售罄可候补；关键词/时间/状态/场次/票种组合筛选；时间最新在前 |
| UI-03 | 报名购票与候补 | 参与者 | 报名、退票/候补 | 有票直接报名、售罄加入候补、支付标记、截止提示 |
| UI-04 | 我的票与退票 | 参与者 | 报名、退票、候补 | 筛选：全部/待检票/已检票/候补中/已结束/已取消/已退票；待检票=已购票；已结束=正常结束+未检票；已取消/已退票=自行取消+活动取消 |
| UI-05 | 组织者活动管理 | 组织者 | 活动/场次、票种、审核 | 草稿/待审核/公开、可修改范围、提交审核 |
| UI-06 | 组织者名单与统计 | 组织者 | 查询统计 | 手机号遮挡、导出、报名/出席/退票率 |
| UI-07 | 管理员审核与处置 | 管理员 | 管理员处置、活动 | 审核队列、举报、封禁、强制退票、创建检票账号 |
| UI-08 | 检票员工作台 | 检票员 | 检票 | 负责活动、请求列表、通过/异常、检票时间窗 |
| UI-09 | 审计日志与权限 | 管理员 | 留痕与权限 | 按对象/操作人/时间筛选、角色可见范围 |

## 4. 角色导航

- 参与者：活动、我的票、通知；
- 组织者：活动管理、名单统计、通知；
- 检票员：检票工作台、负责活动；
- 管理员：审核处置、全平台数据、审计、账号管理。

导航只显示当前角色可用的入口；不可用操作不出现，而不是灰掉后仍可点击。

## 5. 状态与约束

- 售罄：显示“已售罄 / 可候补”，报名按钮切换为“加入候补”；
- 截止：超过报名/退票截止，按钮禁用并说明原因；
- 权限：检票员看不到完整名单和完整手机号；组织者名单手机号遮挡；
- 候补状态：未候补（未提交）→ 支付成功后变为候补中；之后为已递补/候补失败/自行取消。只展示状态和递补结果，不展示队列顺序、候补人数等需求未定义的信息；
- 空/错/加载：列表空状态、加载骨架、提交失败提示；
- 危险操作：取消活动、强制退票、封禁需要二次确认。

## 6. Figma 使用步骤

1. 浏览器打开 figma.com，新建文件“实验二 UI”；
2. 把 `01_登录注册.svg` 拖入画布，作为 1440×900 的 Frame；
3. 检查字体是否显示为 Noto Sans CJK SC / Microsoft YaHei；如缺失，统一替换；
4. 调整颜色、文案、间距，补充悬停/禁用/空状态；
5. 选中 Frame → Export → PNG 2x，命名为 `01_登录注册.png`；
6. 其余八屏同样处理；确认风格后统一导出 9 张 PNG。

> 当前 3 屏是 AI 生成的 SVG 骨架，不是最终稿；你在 Figma 里的调整会作为“人工修改”记录到 AI 使用记录。
