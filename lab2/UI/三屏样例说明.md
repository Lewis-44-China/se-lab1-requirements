# 三屏样例说明

当前先做 3 屏，确认风格、信息密度和 Figma 流程后，再批量做剩下 6 屏。

## 01 登录/注册

文件：`01_登录注册.svg`

- **覆盖模块**：账号（D6/A0）。
- **页面结构**：左侧品牌介绍；右侧登录卡；右侧注册身份引导卡。
- **关键内容**：
  - 登录：只需手机号 + 密码；按 REQ-002/047，一个手机号只对应一个身份，不再选择登录身份；
  - 注册：右侧注册卡选择参与者/组织者身份；管理员、检票员账号由平台预创建；
  - 顶部不再有“注册”Tab，注册入口只在右侧注册卡；
  - 管理员/检票员通过登录卡底部的“登录入口”进入；
  - 不提供“忘记密码/自助找回”；
  - 左侧文案为“不辜负每一份热爱”。
- **需要你在 Figma 中调整**：
  - 品牌区文案/配色是否符合你的审美；
  - 密码框眼睛图标、输入框圆角和间距。

## 02 活动浏览与详情

文件：`02_活动浏览与详情.svg`

- **覆盖模块**：活动/场次、票种/容量、查询统计（只读）。
- **页面结构**：顶部导航；搜索/筛选；左侧活动列表；右侧场次票种详情。
- **关键内容**：
  - 活动类型以演唱会/音乐节（音乐）和戏剧演出为主，保留讲座，**移除运动**；
  - 筛选：关键词、分类快捷（全部/音乐/戏剧/讲座）、时间范围、活动状态、场次、票种；
  - 排序：**时间最新在前**，对应 REQ-029；
  - 活动卡片：封面、时间、地点、分类、票价、余票、状态（售票中/即将售罄/可候补）；
  - 详情：场次切换、VIP/普通票余票、选择按钮、报名截止/退票截止、立即报名；
  - 售罄活动显示“可候补”。
- **需求核对**：
  - REQ-029 要求参与者可按关键词、时间范围、活动状态、场次、票种组合查询，并可按下单/活动时间排序（新的在前）；本屏已覆盖这些条件；
  - 分类快捷是额外便利，不替代上述筛选条件。
- **需要你在 Figma 中调整**：
  - 卡片封面是否要用真实图片（Figma 里放图片填充）；
  - 右侧详情是否改成弹窗/抽屉；
  - 筛选条件展开/收起后的布局；
  - 活动列表空状态、加载状态是否要补。

## 03 报名购票与候补

文件：`03_报名购票与候补.svg`

- **覆盖模块**：报名与支付标记、退票与候补。
- **页面结构**：面包屑；步骤条；左侧报名表单；右侧候补说明。
- **关键内容**：
  - 普通票已售罄 → 候补登记；VIP 票有余票 → 可直接报名（展示两种路径）；
  - 报名信息：姓名、手机号；一单一张、不支持代报名；
  - 支付标记：平台内标记，不接真实支付；
  - 候补截止、递补规则、未成功全额退款；
  - 右侧候补步骤：入队尾 → 等待释放 → 递补/退款。
- **需要你在 Figma 中调整**：
  - 有票状态和售罄状态是否做成两个 Frame；
  - “当前候补人数 12 人”是否保留（真实系统里可以是真实数字）；
  - 支付标记的文案是否再弱化，避免误解为真实支付；
  - 按钮颜色/危险操作提示。
