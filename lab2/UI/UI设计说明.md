# 实验二 UI 设计说明

本文件合并 UI 设计规范、三屏样例说明、其余六屏说明、Figma 导入导出说明和示例数据说明，供实验报告第 4 章直接引用。最终交付图在 `../UI界面/`；`UI/` 保留 SVG 源稿和生成脚本。

## 1. 设计规范

版本：v0.1（三屏样例阶段）  
工具：Figma 网页版  
画布：1440 × 900（桌面端）  
导出：PNG 2x，按 `01_登录注册.png` 这类名称放入 `UI界面/`。

### 1. 设计目标

- 覆盖实验一的 8 个业务模块，每个模块至少一屏；
- 体现四类角色的**入口差异、数据可见性和操作限制**；
- 静态高保真即可，不写前端代码；
- 视觉服务于信息层级：余票、状态、截止时间、权限提示必须一眼可见。

### 2. 设计系统

#### 2.1 颜色

| 用途 | 色值 |
|---|---|
| 主色 | `#2563EB` |
| 主色深 | `#1D4ED8` |
| 浅蓝底 | `#EFF6FF` |

| 次要文字 | `#475569` |

| 边框 | `#E2E8F0` |

#### 2.2 字体

- 中文：Noto Sans CJK SC / Microsoft YaHei；
- 数字与价格：同字体，价格加粗；
- 层级：H1 30–32、H2 22–24、H3 16–18、正文 13–14、辅助 11–12。

#### 2.3 间距与圆角

- 8px 网格；页面左右边距 32px；
- 卡片圆角 14–16px，输入框/按钮 10–12px，标签 8–12px；
- 卡片间距 16px。

#### 2.4 组件

按钮（主/次/幽灵/危险）、输入框、下拉、标签 Chips、状态徽章、活动卡片、票种行、表格、步骤条、提示条、空/加载/错误状态。

### 4. 角色导航

- 参与者：活动、我的票、通知；
- 组织者：活动管理、名单统计、通知；
- 检票员：检票工作台、负责活动；
- 管理员：审核处置、全平台数据、审计、账号管理。

导航只显示当前角色可用的入口；不可用操作不出现，而不是灰掉后仍可点击。

### 5. 状态与约束

- 售罄：显示“已售罄 / 可候补”，报名按钮切换为“加入候补”；
- 截止：超过报名/退票截止，按钮禁用并说明原因；
- 权限：检票员看不到完整名单和完整手机号；组织者名单手机号遮挡；
- 候补状态：未候补（未提交）→ 支付成功后变为候补中；之后为已递补/候补失败/自行取消。只展示状态和递补结果，不展示队列顺序、候补人数等需求未定义的信息；
- 空/错/加载：列表空状态、加载骨架、提交失败提示；
- 危险操作：取消活动、强制退票、封禁需要二次确认。

### 6. Figma 使用步骤

1. 浏览器打开 figma.com，新建文件“实验二 UI”；
2. 把 `01_登录注册.svg` 拖入画布，作为 1440×900 的 Frame；
3. 检查字体是否显示为 Noto Sans CJK SC / Microsoft YaHei；如缺失，统一替换；
4. 调整颜色、文案、间距，补充悬停/禁用/空状态；
5. 选中 Frame → Export → PNG 2x，命名为 `01_登录注册.png`；
6. 其余八屏同样处理；确认风格后统一导出 9 张 PNG。

> 当前 3 屏是 AI 生成的 SVG 骨架，不是最终稿；你在 Figma 里的调整会作为“人工修改”记录到 AI 使用记录。

### 7. 九屏样例

- `01_登录注册.svg`：登录卡 + 注册身份引导卡；
- `02_活动浏览与详情.svg`：活动列表 + 右侧场次/票种详情；
- `03_报名购票与候补.svg`：售罄候补登记 + 支付标记 + 候补说明；

前三屏说明见 `三屏样例说明.md`；其余六屏见 `其余六屏说明.md`。

## 2. 三屏样例说明

当前先做 3 屏，确认风格、信息密度和 Figma 流程后，再批量做剩下 6 屏。

### 01 登录/注册

文件：`01_登录注册.svg`

- **覆盖模块**：账号（D6/A0）。
- **页面结构**：左侧品牌介绍；右侧登录卡；右侧注册身份引导卡。
- **关键内容**：
  - 登录：只需手机号 + 密码；按 REQ-002/047，一个手机号只对应一个身份，不再选择登录身份；
  - 注册：右侧注册卡选择参与者/组织者身份；管理员、检票员账号由平台预创建；
  - 顶部不再有“注册”Tab，注册入口只在右侧注册卡；
  - 管理员/检票员通过登录卡底部的“登录入口”进入；
  - 不提供“忘记密码/自助找回”；
  - 左侧文案为“不辜负每一份热爱”。
- **需要你在 Figma 中调整**：
  - 品牌区文案/配色是否符合你的审美；
  - 密码框眼睛图标、输入框圆角和间距。

### 02 活动浏览与详情

文件：`02_活动浏览与详情.svg`

- **覆盖模块**：活动/场次、票种/容量、查询统计（只读）。
- **页面结构**：顶部导航；搜索/筛选；左侧活动列表；右侧场次票种详情。
- **关键内容**：
  - 活动类型以演唱会/音乐节（音乐）和戏剧演出为主，保留讲座，**移除运动**；
  - 筛选：关键词、分类快捷（全部/音乐/戏剧/讲座）、时间范围、活动状态、场次、票种；
  - 排序：**时间最新在前**，对应 REQ-029；
  - 活动卡片：封面、时间、地点、分类、票价、余票、状态（售票中/即将售罄/可候补）；
  - 详情：场次切换、VIP/普通票余票、选择按钮、报名截止/退票截止、立即报名；
  - 售罄活动显示“可候补”。
- **需求核对**：
  - REQ-029 要求参与者可按关键词、时间范围、活动状态、场次、票种组合查询，并可按下单/活动时间排序（新的在前）；本屏已覆盖这些条件；
  - 分类快捷是额外便利，不替代上述筛选条件。
- **需要你在 Figma 中调整**：
  - 卡片封面是否要用真实图片（Figma 里放图片填充）；
  - 右侧详情是否改成弹窗/抽屉；
  - 筛选条件展开/收起后的布局；
  - 活动列表空状态、加载状态是否要补。

### 03 报名购票与候补

文件：`03_报名购票与候补.svg`

- **覆盖模块**：报名与支付标记、退票与候补。
- **页面结构**：面包屑；步骤条；左侧报名表单；右侧候补说明。
- **关键内容**：
  - 普通票已售罄 → 候补登记；VIP 票有余票 → 可直接报名（展示两种路径）；
  - 报名信息：姓名、手机号；一单一张、不支持代报名；
  - 支付标记：平台内标记，不接真实支付；
  - 候补截止、递补规则、未成功全额退款；
  - 最后一句明确：候补成功只是加入候补队列，不保证最终买到票；
  - 当前页面还未提交，所以右侧状态是“未候补 / 支付后加入候补队列”；支付成功、生成候补记录后才变为“候补中”；
  - 右侧候补步骤：入队尾 → 等待释放 → 递补/退款；不展示队列顺序、候补人数等需求未定义的信息。
- **需要你在 Figma 中调整**：
  - 有票状态和售罄状态是否做成两个 Frame；
  - “当前候补人数 12 人”是否保留（真实系统里可以是真实数字）；
  - 支付标记的文案是否再弱化，避免误解为真实支付；
  - 报名信息标题与“姓名”标签的间距（已上移标题，Figma 中可再微调）；
  - 按钮颜色/危险操作提示。

## 3. 其余六屏说明

这六屏与前面三屏使用同一套设计系统和 1440×900 画布。图中的人数、场次、活动名称等均为演示数据，不是需求中的硬性数值；不同界面之间的示例数据不要求完全一致，详见 `示例数据说明.md`。

### UI-04 我的票与退票

文件：`04_我的票与退票.svg`

- **角色/模块**：参与者；报名与支付标记、退票与候补。
- **内容**：
  - 筛选分类：全部 / 待检票 / 已检票 / 候补中 / 已结束 / 已取消/已退票；
  - 卡片示例：11月1日戏剧已检票、11月8日音乐节待检票、11月16日古典音乐会候补中、11月20日设计沙龙已退票；日期与状态保持先后一致；
  - 待检票 → 可申请退票；已检票 → 不可退票；
  - 候补中 → 候补记录，不是报名记录，尚未取得票；可取消候补；
  - 已退票 → 对应报名状态“自行取消”，显示退款金额；
  - 右侧退票与候补说明；“一单一张”属于购票规则，放在 UI-03，不放在退票说明里。
- **筛选归纳（仅 UI，不改变系统状态）**：
  - 待检票 = 报名状态 `已购票`（有效票，尚未检票）；
  - 已检票 = `已检票`；
  - 候补中 = 候补记录 `候补中`；
  - 已结束 = `正常结束` + `未检票`（缺席）；
  - 已取消/已退票 = `自行取消` + `活动取消`；卡片仍显示“已退票/活动取消”具体原因；
  - 已递补转为报名记录后进入待检票/已检票；候补失败归入候补记录历史。
- **约束**：不提供删除报名记录；退票/取消后进入终态，记录仍可查询。
- **Figma 调整**：可增加“正常结束/未检票/已递补/候补失败”状态变体；退票确认弹窗可另做 Frame。

### UI-05 组织者活动管理

文件：`05_组织者活动管理.svg`

- **角色/模块**：组织者；活动与场次、票种与容量、审核。
- **内容**：
  - 顶部统计：进行中/待审核/草稿/已结束；
  - 活动表格：活动、场次、状态、报名/容量、最近更新、操作；
  - 操作按状态区分：
    - 进行中：查看 · 编辑资料 · 场次票种 · 申请修改 · 申请取消；
    - 待审核：查看（不能编辑）；
    - 草稿：编辑 · 场次票种 · 提交审核；
    - 已结束：查看 · 名单 · 统计；
  - 右侧“组织者权限与修改规则”：
    - 可见范围：仅自己创建的活动；不提供公开活动查询；不能查看其他组织者的活动与报名；
    - 可直接修改：描述/图片/标签；
    - 需重新审核：时间/地点（无论开售前后）、容量/票价（仅开售前）；时间修改后通知已购票人；
    - 禁止修改：开售后容量/票价；已结束/已取消不可修改；
    - 取消活动：组织者申请取消需管理员审批，未审批前不进入取消；
    - 审核不通过退回草稿，可修改后重新提交。
- **需求对照**：
  - REQ-002/029：组织者只能查看自己创建的活动及其报名，不提供公开活动查询；
  - REQ-006～REQ-008：创建活动、场次、票种，填写容量/价格；
  - REQ-009：提交审核，驳回退回草稿，可修改后重新提交；
  - REQ-010/REQ-028：描述/图片/标签直接改；时间/地点重新审核；容量/票价开售前可改且重新审核，开售后禁止；时间修改通知购票人；
  - REQ-011：组织者取消需管理员审批，未审批前不进入取消；
  - REQ-030/031：名单、统计、导出在 UI-06。
- **Figma 调整**：创建活动可另做向导 Frame；操作列按钮可拆成下拉菜单。

### UI-07 管理员审核与处置

文件：`07_管理员审核与处置.svg`

- **角色/模块**：管理员；审核、账号与管理员处置。
- **内容**：
  - 三个 Tab：活动审核 / 举报处理 / 账号与处置；
  - 左侧“待审核申请 3”，每条标出类型：发布审核 / 修改审核 / 取消申请；
  - 当前选中的示例是“城市音乐节 · 夏日专场”的**修改审核**，右侧显示本次修改前后对比（时间、地点、容量/票价），与左侧类型一致；
  - 审核意见输入框，通过/驳回按钮；
  - 底部“相关处置”：取消活动、强制退票、封禁组织者、创建检票账号；
  - 举报处理不再放在活动审核的快捷处置里，它属于单独的“举报处理”Tab。
- **需求对照**：
  - REQ-009：活动发布必须审核，一周内完成；驳回退回草稿；
  - REQ-010/011：修改审核、取消申请进入管理员审批；
  - REQ-018：举报处理是独立模块/Tab，不与活动审核快捷处置混在一起；
  - REQ-048：强制退票；REQ-047：创建检票账号；
  - REQ-002：管理员不能修改用户个人信息，查看个人信息仅限运营、举报、封禁所需。
- **约束**：管理员不能修改用户个人信息；查看个人信息仅限运营、举报、封禁所需。
- **Figma 调整**：举报处理/账号处置可分别做独立 Frame；审核意见可加常用理由模板。

### UI-08 检票员工作台

文件：`08_检票员工作台.svg`

- **角色/模块**：检票员；检票。
- **内容**：
  - 只显示负责的活动与检票时间窗；非开放时间不能发起/处理；
  - 待处理请求列表：请求编号、遮挡姓名、票种、请求时间；
  - 右侧详情：报名状态、场次、检票时间窗；
  - “通过检票 / 标记异常”；
  - 岗位约束：只能处理负责活动的请求；不能修改报名状态；不能访问完整名单或完整手机号；手动勾选检票，无扫码/二维码入口；异常标记写入留痕；不记录缺席；重复检票只有第一次有效。
- **需求对照**：
  - REQ-014：参与者在检票开放时间内发起请求，检票员处理；不能直接修改报名状态；
  - REQ-015：手动勾选检票，不采用二维码；
  - REQ-016：检票员不记录缺席，场次结束后由系统转“未检票”；
  - REQ-017：凭证不符标记异常，不通过，并写入留痕；
  - REQ-036：重复检票只有第一次有效，后续提示“已检票”，不禁止入场；
  - REQ-003/045：只访问负责活动的请求，不访问完整名单和完整手机号。
- **约束**：检票员只能处理负责活动的请求；凭证不符标记异常，不通过。
- **Figma 调整**：可增加“已处理”Tab、检票时间未开放的禁用状态。

### UI-09 审计日志与权限

## 4. Figma 导入与导出

### 1. 打开 Figma

浏览器打开 https://www.figma.com ，登录免费账号，新建一个 Design 文件，命名“实验二 UI”。

### 2. 导入 SVG

1. 在文件里把需要的 SVG（目前 9 个）直接拖进画布；
2. Figma 会把它作为可编辑图层导入；
3. 选中导入的顶层 Frame，在右侧把尺寸设为 `1440 × 900`；
4. 如果字体提示缺失，选中文本，把字体统一改为 `Noto Sans CJK SC` 或 `Microsoft YaHei`；
5. 用同样的方式导入其余八屏 SVG。

### 3. 调整建议

- 先不要重画结构，只改：颜色、字号、间距、文案、图片填充；
- 需要交互状态时，复制 Frame 做“售罄/禁用/空状态”变体；
- 需要图片封面时，用 Figma 的图片填充替换 SVG 里的渐变色块；
- 每个 Frame 命名与导出文件名一致，例如 `01_登录注册`。

### 4. 导出 PNG

1. 选中 Frame；
2. 右侧面板底部 Export → `+` → 选择 PNG；
3. 倍率选 `2x`；
4. Export 保存为 `01_登录注册.png`；
5. 九张都导出后，放到 `lab2/UI界面/` 或先发给我检查。

### 5. 注意

- 最终 zip 只需要 PNG；SVG 源文件保留在仓库里，不放进交付包；
- 不要直接把 SVG 当最终 UI 交，Figma 调整后的 PNG 才是设计结果；
- 你在 Figma 里的修改会作为人工修改记录，后续写进 AI 使用章节。

## 5. 示例数据说明

本目录及 `UI界面/` 中的 9 张 UI 图，重点是展示**页面结构、角色入口、操作状态和权限边界**，图中数据均为演示数据。

### 需要说明的内容

以下内容均为示例，不代表真实业务数据，也不要求跨图完全一致：

- 活动名称、组织者姓名；
- 活动时间、地点；

### 为什么跨图可能不一致

这些图是在设计过程中分批制作的，示例数据用于展示不同状态（待检票、已检票、候补中、已退票、待审核、草稿、已结束等）。不同图可能使用不同的示例活动或日期，目的是把状态覆盖完整，而不是构造一套跨图一致的数据集。

**系统规则、状态集合、权限边界以 `00_设计基线.md`、UML 图和实验一需求为准；UI 图中的数字和名称只作展示。**
