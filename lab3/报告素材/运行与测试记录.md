## 3. 端到端手工验证

以下流程已实际运行（终端管道输入）：

1. **参与者退票 → 候补自动递补**
   - 参与者 1 退掉活动 1 的普通票；
   - 下一次菜单循环 `Scheduler.tick()` 消费 Outbox；
   - 候补队首（参与者 2）自动生成报名记录，候补状态变为“已递补”。
2. **参与者发起检票 → 检票员处理**
   - 参与者 4 对活动 2 发起检票请求；
   - 检票员看到请求，手机号显示为 `136****0004`；
   - 检票员选择“通过”，报名记录变为“已检票”，审计写入两条记录。
3. **组织者统计与名单导出**
   - 活动 3：报名人数 3、出席 2、退票 1，出席率 66.7%、退票率 25.0%；
   - 名单手机号遮挡；导出 CSV 仅含姓名/场次/票种，不含手机号。
4. **管理员审核与举报处置**
   - 管理员审核组织者新建活动的发布申请，活动变为公开；
   - 处理活动 2 的举报，选择“举报属实 + 取消活动”；
   - 活动 2 变为“已取消”，两条报名记录变为“活动取消”并退款。
5. **并发抢最后名额**
   - 8 个线程同时报名容量为 1 的普通票；
   - 恰好 1 个成功、7 个 `CapacityFull`；
   - `ticket_type.occupied = 1`，报名记录 1 条。

## 4. 自动化测试

命令：

```bash
python3 -m unittest discover -s tests -t . -v
```

结果（完整输出见 `测试输出.txt`）：

- 共 **40 个测试**，全部通过；
- 运行时间约 26 秒（每个测试独立临时数据库，PBKDF2 口令哈希占主要时间）。

测试分布：

| 文件 | 覆盖内容 | 数量 |
|---|---|---|
| `tests/test_core.py` | 认证、活动审核、修改规则、报名幂等、名额并发 | 19 |
| `tests/test_lifecycle.py` | 候补 FIFO/递补/取消/截止、退票、检票、时间推进、封禁 | 15 |
| `tests/test_queries.py` | 公开查询、名单遮挡、CSV、统计、审计范围、平台概览 | 6 |

代表性测试：

- `test_concurrent_last_seat_only_one_wins`：8 线程抢 1 个名额；
- `test_same_request_id_is_idempotent`：同一请求返回同一记录；
- `test_register_at_sale_end_is_allowed` / `...after_sale_end_fails`：截止时刻边界；
- `test_fifo_and_promotion`：候补 FIFO 与自动递补；
- `test_session_end_marks_no_show_and_normal_end`：缺席不释放名额；
- `test_audit_scope_by_role`：组织者/参与者/管理员审计可见范围。

## 7. 注意事项

- 在非交互管道中运行 `getpass` 会提示“密码可能回显”，这是 Python 的
  非 TTY 警告；正常终端不会出现。
- 演示数据的时间相对启动时刻生成；隔天再演示可 `python3 main.py --reset`
  重建，或重新生成数据库。
- 数据库、`__pycache__`、导出的 CSV 不进入 Git 与交付 zip。
